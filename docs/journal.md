# Журнал работы

Короткие записи после каждого этапа: что сделано, какие решения приняты, что осталось.

## Этап 0. Окружение (2026-10-31)
- База — локальный PostgreSQL 16 (Homebrew). `docker-compose.yml` лежит в репозитории, но не запускался. Разница с SQLite описана в `docs/sqlite_vs_postgres.md`.
- Python 3.14.
- API hh.ru на анонимный запрос ответил `403 {"errors":[{"type":"forbidden"}]}`. Работаем на фикстурах — синтетических ответах в формате API (см. README). Режим `DATA_SOURCE=api` реализован и включается токеном.

## Этап 3. ETL
- `scripts/generate_fixtures.py` — синтетический «мир» в формате API hh.ru (seed=42): 1163 вакансии, 1989 версий. В базу за период до 30 октября попадают 1162 вакансии (одна опубликована 1 ноября) и 1895 версий. `FixtureClient` показывает мир «на дату» — так команда `backfill` воспроизводит 244 ежедневных запуска и накапливает историю.
- `src/extract`: общий интерфейс `BaseClient` с пагинацией; `HHClient` — повторы на 429/5xx/сетевых ошибках с экспоненциальной задержкой и jitter, `Retry-After`, таймауты, пауза между запросами, User-Agent. 403/400 не повторяются.
- `src/transform`: плоские записи, нормализация навыков, роль по названию, `content_hash`.
- `src/load`: upsert с `ON CONFLICT`, одна транзакция на вакансию, SCD2 по `content_hash`, `load_run`.
- Решение по ходу: соединение в режиме `autocommit=True` + явные `conn.transaction()` — иначе в psycopg 3 вложенные транзакции становятся SAVEPOINT и ничего не коммитится.
- Решение по ходу: `valid_from` версии = `published_at`, а не время запуска. Иначе история зависела бы от расписания загрузок.
- **Найденная ловушка:** часовой пояс сервера PostgreSQL на машине — `Asia/Tomsk`. `first_seen_at::date` для 23:59 МСК давал следующий день. Во всех запросах по датам используем `AT TIME ZONE 'Europe/Moscow'`.
- Тесты: 49 штук (transform, extract без сети, загрузка на тестовой БД: идемпотентность, падение на середине, SCD2, защита от отката, SQL-инъекция, CHECK).

## Этап 4. SQL-аналитика
- `sql/queries/q1…q6` + `q1b` (для тепловой карты). Приёмы: CTE, `ROW_NUMBER`, `RANK`, `LAG` с `WINDOW`, `count(*) OVER`, `percentile_cont`, `GROUPING SETS`, `ROLLUP`, `FILTER`, `HAVING`, `LEFT JOIN ... IS NULL`, коррелированный подзапрос, gaps-and-islands.
- Для замеров создана база `vacancies_bench` (300 тыс. вакансий, `scripts/bench_scale.sql`).
- q6: 4043 → 143 мс. Причина — коррелированный подзапрос по CTE (5009 проходов). Переписан через оконную функцию.
- q5: 1300 → 109 мс. Миграция `sql/002_indexes.sql`: индекс по `first_seen_at` и составной индекс по выражению `(employer_id, area_id, lower(name), created_at)`.
- q2: гипотеза «не хватает work_mem» проверена и не подтвердилась. Оставлен как есть, путь ускорения — материализованное представление.
- По ходу: «возможный дубль» в q5 без ограничения по времени срабатывал на любой повторяющийся заголовок. Ограничили 14 днями.

## Этап 5. Анализ и визуализация
- `src/report.py`: 4 PNG + 7 CSV в `reports/`, данные для сайта в `explainer/data.js`. Пояснения к графикам — `reports/README.md`.
- У трёх ролей три разных цвета, тепловая карта — одна синяя шкала.
- Доля без зарплаты показана с 95 % интервалами Уилсона: Москва и Томск различаются устойчиво, Казань и Нижний Новгород — нет.
- Вывод: тренд +1,2 %/мес, заложенный в генератор, на графике не виден — шум маленьких выборок больше.
- `src/api.py` — `/api/summary` на FastAPI + тест. Ещё раз всплыл часовой пояс: psycopg отдаёт время в поясе сессии (+07).

## Этап 6. Интерактивное объяснение
- `explainer/`: `index.html`, `styles.css`, `app.js`, тексты в `content-1..3.js`, данные в `data.js` (генерирует `report`). Без библиотек и `fetch` — открывается двойным кликом.
- 8 разделов на русском и английском: схема с анимацией пути вакансии, результаты (5 SVG-графиков с подсказками и табличным видом), требования, интерактивная ER-диаграмма, 3 ETL-демо (пагинация, retry, upsert в 4 режимах), 6 пошаговых SQL-разборов, 6 ADR с альтернативами, 16 проблем и решений.
- Проверка: `scripts/check_explainer.py` (Playwright, file://) — консоль без ошибок, все кнопки и шаги срабатывают, на 375 px нет горизонтальной прокрутки. По ходу исправлено: переполнение на телефоне, слипшиеся связи ER-диаграммы, обрезанный SQL в уроках.
